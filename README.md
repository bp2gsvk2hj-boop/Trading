# Trading

Торговые стратегии.

- [`hft/`](hft/) — высокочастотный маркет-мейкер для фьючерсов Московской биржи (FORTS): стратегия, риск-менеджмент, событийный бэктест.

## HFT маркет-мейкер для FORTS

### Стратегия

Пассивный маркет-мейкинг с альфой из микроструктуры стакана (`hft/strategy.py`):

1. **Справедливая цена** = mid + альфа. Альфа складывается из
   - microprice (mid, взвешенный объёмами лучших уровней),
   - многоуровневого дисбаланса стакана (OBI),
   - дисбаланса агрессивного потока сделок за последние секунды.
2. **Сдвиг на инвентарь.** Цена резервирования смещается против накопленной позиции
   (как в модели Avellaneda–Stoikov), чтобы позиция возвращалась к нулю.
3. **Котировки** по обе стороны вокруг цены резервирования; ширина растёт с волатильностью.
4. **Фильтр токсичности.** Сторону, где ожидаемый край после комиссии ниже порога,
   не котируем: при сильном давлении вниз снимаем покупку, и наоборот.
5. **Опциональный тейкер**: при сильной альфе пересекаем спред IOC-заявкой.

Риск (`hft/risk.py`): лимит позиции с учётом выставленных заявок, дневной лимит убытка
с аварийным закрытием (kill switch), лимит частоты команд, снятие котировок при устаревшем стакане.
Расписание (`hft/sessions.py`): котируем только внутри торговых окон и закрываем позицию
перед дневным и вечерним клирингом.

### Архитектура

```
стакан/сделки ──► Trader ──► OBIMarketMaker.quotes()  ──► целевые котировки
                    │  ▲          RiskManager                    │
                    │  └── ack / cancel / fill ◄──┐              ▼
                    └── PlaceOrder / CancelOrder ─►  Venue: SimulatedExchange (бэктест)
                                                            или BrokerConnector (live)
```

Один и тот же `Trader` работает в бэктесте и вживую — меняется только площадка.

| Модуль | Назначение |
|---|---|
| `hft/types.py` | стакан, сделки, заявки, команды |
| `hft/instruments.py` | спецификации Si, RTS и модель комиссий |
| `hft/signals.py` | OBI, microprice, поток сделок, волатильность |
| `hft/strategy.py` | логика котирования |
| `hft/trader.py` | управление заявками, учёт позиции и PnL |
| `hft/risk.py`, `hft/sessions.py` | лимиты и расписание торгов |
| `hft/backtest/` | симулятор биржи с очередью и задержкой, загрузка CSV, синтетика, метрики |
| `hft/connectors/` | интерфейс брокера и каркасы ALOR / T-Invest (не реализованы) |

### Симулятор исполнения

- Команды доходят до биржи с задержкой `--latency-ms`, ответы возвращаются с той же задержкой.
- Пассивная заявка встаёт в конец очереди своего уровня; очередь сокращается сделками
  по этой цене и уменьшением уровня в стакане.
- Исполнение: объём сделок превысил очередь впереди, сделка прошла сквозь цену заявки
  или стакан пересёк её цену.

### Запуск

```bash
pip install -e .[dev]
python -m pytest
python -m hft.backtest.run --synthetic --seconds 3600          # синтетика
python -m hft.backtest.run --instrument Si --book book.csv --trades trades.csv \
    --maker-fee 0.5 --taker-fee 1.0 --latency-ms 2
```

Формат CSV описан в `hft/backtest/data.py`. Параметры стратегии можно передать JSON-файлом
`--config params.json` (поля `MarketMakerConfig`).

### Что важно знать до реальной торговли

- **Синтетика ничего не говорит о доходности.** В генераторе дисбаланс стакана намеренно
  предсказывает цену; на синтетике проверяется только механика. Нужен бэктест на реальных
  данных — стакан и лента сделок Si/RTS (MOEX AlgoPack/DataShop или собственная запись
  через API брокера), лучше полный ордерлог.
- **Комиссии решают всё.** Спред Si обычно один шаг (1 руб.), поэтому комиссия брокера
  и биржи в несколько рублей за контракт делает пассивный маркет-мейкинг убыточным.
  Комиссии в `hft/instruments.py` — заглушки, подставьте свой тариф.
- **Сбор за неэффективные транзакции.** Биржа штрафует за большое число заявок на сделку;
  в отчёте есть показатель «контрактов на заявку», лимит частоты — в `RiskConfig`.
- **Задержка.** Настоящий HFT на MOEX — это колокация и шлюзы биржи (Plaza II / TWIME / FIX).
  Через ALOR OpenAPI или T-Invest API задержка — миллисекунды и десятки миллисекунд;
  прогоняйте бэктест с реалистичной `--latency-ms` и ожидайте ухудшения результата.
- Коннекторы к брокерам пока только каркасы с планом реализации.
